# Blade 统一事件溯源（Event Sourcing + CQRS）改造

## Context

用户在调研主流 coding agent（Codex、Claude Code、Grok Build）的架构后确认：Codex 和 Grok Build 采用了完整的 Event Sourcing + CQRS——一条 append-only 事件流作为唯一真相源，TUI/持久化/查询都是它的投影（projection）。Blade 的持久化层（JSONL + `materializeSessionEvents()`）已经接近这个形态，但整体架构没有闭环。

用户明确要求：**做最合理的目标架构，不考虑工作量与向后兼容**，且必须同时覆盖 CLI Ink UI、Web 模式、ACP 模式，做充分测试，Web 端要做**真正的浏览器 GUI 测试**。

### 现状的根因：三套割裂的"事件"

| 事件 | 位置 | 问题 |
|---|---|---|
| `LoopEvent` | agent loop 产出（`services/pi/streamAdapter.ts`） | `content_delta`/`tool_start`… 只在内存流转 |
| `BusEvent` | `server/bus.ts` | 纯 fan-out，**无 seq、无 buffer** |
| `SessionEvent` | `context/types.ts` L118-263 | JSONL 持久化，**append 时无 emit**，与 Bus 完全解耦 |

三套各转一次、各存一份；CLI Zustand store（`store/slices/sessionSlice.ts`）还完全独立 `set(state=>...)` mutate，不从事件派生。结果：持久化、Bus、store 三条路径可能不一致；SSE 断线只能全量刷新；结果性事件（tool、token_usage）不落盘，replay 无法重建完整历史。

### 目标

一条带单调 `seq` 的统一事件流作为唯一真相源。CLI store、Web SSE、ACP、持久化全部退化为其纯投影，支持 `Last-Event-ID` 断点续传与 replay 重建。

---

## 核心设计：两层事件模型

这是整个改造的关键决策。**不把三套事件塌缩成一个扁平类型**，而是分两层：

### Layer A — Committed Events（持久事实，带 seq）

扩展现有 `SessionEvent`，作为唯一权威类型，`SessionEventBase` 增加字段：

```ts
interface CanonicalEventBase {
  seq: number;          // 每 session 单调递增，由事件日志分配
  id: string;           // 现有 ULID
  sessionId: string;
  projectPath: string;  // 新增（现有仅 sessionId+cwd）
  timestamp: string;
  cwd: string;
  gitBranch?: string;
  version: string;
}
```

在现有 variant（`session_created`/`session_updated`/`session_rewound`/`inbox_acknowledged`/`message_created`/`part_created`/`part_updated`）基础上，**将结果性 LoopEvent 纳入持久事件**：`tool_call_started`、`tool_call_completed`、`token_usage`、`turn_started`、`model_fallback`、`subagent_spawned`/`subagent_completed`、`goal_updated`。这些当前只走 Bus、不落盘，纳入后 replay 才完整。

### Layer B — Ephemeral Deltas（在途增量，不落盘、不占 seq）

`content_delta`/`thinking_delta` 是 UI 渲染优化，**不进 JSONL、不分配 seq**。携带 `anchorSeq`（所属 `part_created` 的 seq）+ turn 内 `deltaIndex`。turn 结束时，loop 发一条 committed `part_updated`（含完整文本）作为该 part 的最终真相，**幂等覆盖**之前的 delta 投影。

**这解决了"流式增量与持久事件如何共存"的核心矛盾**：delta 永不 replay，replay 只回放最终 part 文本；重连时若 turn 在途，从 anchor part 的当前 committed 文本开始，后续 delta 实时补。JSONL 保持精简，seq 语义纯净。

## 目标模块结构

新建目录 `packages/cli/src/context/events/`：

- `CanonicalEvent.ts` — TypeBox schema + TS 类型（Layer A）
- `EphemeralDelta.ts` — delta 类型（Layer B）
- `SessionEventLog.ts` — **唯一写入者**，每 session 一个实例
- `reducers/conversationReducer.ts` — 纯 reducer，三端共享

### SessionEventLog（单写入者）

```ts
class SessionEventLog {
  private seq = 0;                     // 恢复时 = max(committed.seq)
  private ring: CanonicalEvent[] = []; // 最近 N 条（512）环形缓冲
  async commit(evt: EventInput): Promise<CanonicalEvent>; // 分配 seq → JSONLStore.append → 入 ring → fanout
  emitDelta(d: EphemeralDelta): void;                     // 仅 fanout，不落盘
  subscribe(cb, opts?: { fromSeq?: number }): Unsub;      // 从 ring/JSONL 补发
}
```

- `commit()` 复用 `JSONLStore` 现有 per-file `enqueue` 串行队列，保证 seq 与落盘顺序一致。
- **Bus 降级为 SessionEventLog 的 fanout 通道**，不再是独立系统。`session.ts:1822` 的 `emit()` wrapper 改为调 `log.commit()`/`log.emitDelta()`。
- `SessionService`/`PersistentStore` 的 `saveMessage`/`saveToolUse`/`saveToolResult` 改为 `log.commit()` 的薄封装——**持久化与 fanout 从此原子耦合**。

## 各端投影（纯 reducer）

统一契约 `applyEvent(state, evt): state`，各端复用 `conversationReducer`：

- **CLI store** (`store/slices/sessionSlice.ts`)：删除所有命令式 mutation（`addMessage`/`appendAssistantContent`/`finalizeStreamingMessage`…），改为单一 `applyCommitted(evt)`（调 reducer）+ `applyDelta(d)`（更新 streamingBuffer）。`loopEventHandler.ts` 从"映射 15 个 action"退化为"订阅 log → 分发 committed/delta"。UI 只消费不产生状态。
- **Web SSE** (`server/routes/session.ts:1546`)：订阅 `log.subscribe`，committed 写 `writeSSE({ id: String(seq), data })`；delta 用 `event: 'delta'` 且**不写 id**（避免污染 Last-Event-ID 游标）。删除 `events.ts` 只转发 `task.status` 的特例。
- **ACP** (`acp/Session.ts:192`)：从"只订 task.status + loop 直接发通知"改为统一订阅 `log`，committed → ACP notification，delta → session/update 流。
- **Persistence**：已是投影，现由 log 内部完成。

**streamingBuffer 定位**：纯读侧/渲染侧关注点。`useStreamingBuffer.ts` 保留（批处理 delta 降低 Ink 重渲染），输入源从 loopEventHandler 改为 `log` 的 delta 分发；永不参与 committed 状态。

---

## Resume / Replay

- **Last-Event-ID**：Web client (`web/src/services/sessionService.ts`) 改用 EventSource 原生 `Last-Event-ID`，移除自定义 backoff 全量刷新。服务端读 header → `fromSeq = lastId + 1`。
- **补发：ring 优先 + JSONL 兜底**。ring 保留最近 512 条；`fromSeq >= ring[0].seq` 从内存补，否则 `JSONLStore.readFromSeq(seq)`（新增）按 seq 过滤重读。committed 靠 seq 天然幂等去重。
- **在途 delta 重连**：不重放。重连时 committed 补发带出 anchor part 的最新 committed 文本（长 turn 内 loop 周期性 `part_updated` checkpoint，至少 turn 末一次），客户端据此渲染，后续实时 delta 衔接。无需持久化 delta 也不丢内容。

## 关键 trade-off

两层模型引入"delta 不可 replay、依赖 turn 内 committed checkpoint"的约束——代价是长 turn 内 loop 需周期性发 `part_updated`；收益是 JSONL 精简、seq 语义纯净、断线续传无需持久化易失的 delta。
