# Conversation recap

长任务运行时，Blade 会自动在对话中插入简短回顾，帮助你了解当前进展：

> ↶ recap: 目标是完成事件日志改造。任务 1、2 已提交且测试通过，任务 2 的评审仍在进行。接下来处理评审结论，再开始任务 3。

回顾在终端和 Web 中以灰色斜体显示，通常只有两三句话，概括目标、已完成工作、
当前等待或阻塞以及下一步。内容沿用当前会话语言，无需输入命令。

## 何时出现

主 Agent 执行期间，在模型调用之间检查：至少经过两分钟并完成五个新的模型轮次后，
生成一次回顾。成功压缩上下文后也可以触发，但仍遵循两分钟间隔。
短任务、子代理和要求结构化输出的任务不会生成回顾。

每次回顾使用当前模型额外发送一次有界的无工具请求，最多等待十秒，费用计入辅助
Token 使用量。生成失败会跳过，并继续执行主任务。

## 历史与取消

回顾记录的是生成时的状态，保留在会话历史中；恢复会话只重放已有回顾。
它不会进入后续主模型上下文，也不会执行工具、改变任务状态或压缩检查点。
取消主任务会同时取消正在生成的回顾。

输入来自当前有效上下文，包含已有压缩摘要。较长历史会保留最初目标和近期证据；
发生裁剪时，回顾会附带提示。计划、尝试与已验证结果会在提示中要求明确区分。

ACP 以 `recap:` 文本和 `blade/conversationRecap` 元数据投影。
Headless 文本模式写入 stderr；JSONL 模式发送独立的 `conversation_recap` 事件，
包含 `message_id` 和 `text`，与最终回答分开。
