# Conversation recap

## 目标

长任务执行期间自动显示截图所示的行内 `recap:`。用一个短段落说明目标、
已完成进展、当前等待或阻塞以及下一步，让用户重新接上对话。
TUI 使用灰色斜体，Web 使用低强调行内文本，ACP/Headless 保留文本语义。
本功能不提供手动 `/recap` 命令、旁路面板或独立按钮。

## 行为边界

- 在主 Agent 的模型调用之间生成，默认至少间隔 2 分钟且新增 5 个模型轮次。
- 上下文成功压缩后也可触发，但仍遵循 2 分钟限频；短会话、子代理与结构化输出跳过。
- 使用当前模型的单次无工具请求，最多等待 10 秒；失败静默跳过，本轮不重试。
- 结果作为带 `conversationRecap` 标记的展示消息持久化；不进入主模型上下文，
  不改变压缩 checkpoint，不作为任务完成或行动授权依据。
- 只读取已完成模型轮次的上下文；不会包含尚未提交的流式文本。
- 未完成、失败、仅计划执行和已经验证的工作必须区分；缺失的信息明确标注。
- 默认沿用会话语言，输出 2–3 句纯文本；不输出标题或列表。
- 取消主任务时取消回顾请求。恢复历史只重放已有回顾，不自动调用模型。

## 实现位置

1. `ConversationRecapService` 构造有界引用历史和单次 Provider 请求。
   排除系统提示、隐藏控制消息、旧回顾、推理和图片数据，拒绝工具调用和无效输出。
2. `ConversationRecapSchedule` 保存单次 run 的限频状态，先记尝试再生成，失败也限频。
3. Agent loop 在安全边界生成，先持久化再发 `conversation_recap` 事件。
   TUI/ACP/Headless 消费该事件；Web 复用已存在的持久 message/part 流和重放。
4. Session model context 及 TUI 上下文构造统一排除回顾；历史 UI 保留。
5. 渲染只根据明确的 metadata 标记，不把普通正文中的 `recap:` 自动识别为系统回顾。

## 历史预算

从当前有效模型上下文构造输入，继承已有压缩摘要与 rewind 语义。
限制总长度、消息数量与单条工具输出，保留最初用户目标及最近消息，保持时间顺序。
发生裁剪时向用户显示固定提示，不依赖模型自行披露；不得将部分历史称为完整总结。
每条回顾记录生成当时状态；主对话继续后不会用旧回顾替代新的进度事实。

## 验证

- 服务：只读、无工具、语言、输入预算、空会话、异常输出和取消。
- 调度与 loop：限频、失败继续、先持久化后展示、模型上下文不变。
- TUI/Web/ACP：灰色斜体行内展示、历史恢复、无重复消息及主上下文隔离。
- 双语使用文档、类型检查、lint、生产构建、相关及完整回归。
- 真实 Provider 测试遵循项目现有显式执行约定；DeepSeek 仅使用 Flash。
