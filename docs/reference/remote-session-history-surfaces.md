# 远程会话历史界面

从 `0.10.129` 开始，Blade 的 Web GUI 和终端 TUI 可以发现并查看由 ACP
远程工作区保存的会话历史。远程会话以独立的“仅历史”界面打开；它不会把远程路径
当成本机路径，也不会因为查看历史而创建新的 Agent、终端或文件系统权限。

## 状态含义

远程会话行会显示以下信息：

- `Remote` / `远程`：会话属于 ACP 远程工作区；
- `Online` 或 `Offline`：原 ACP owner 当前是否仍以同一精确工作区身份在线；
- `History only` / `仅历史`：当前界面只允许读取已持久化的会话历史；
- 规范化的远程工作目录：仅用于显示，不是访问权限，也不会被转换为本机路径。

即使 owner 已离线，已安全持久化的历史仍可查看和 fork。在线状态也不会让 Web
或 TUI 自动获得远程执行权限。

## Web GUI

1. 使用 `blade web` 打开 Web UI。
2. 在侧边栏的“远程会话”分组中选择带有远程、在线或离线、仅历史标记的会话。
3. 历史视图会显示规范化的远程工作目录和经过白名单投影的用户、助手消息。
4. 点击“加载更早消息”或滚动到已加载内容顶部，可按页读取更早历史。
5. 搜索框只搜索当前已经加载的页面；可复制单条消息。
6. 若会话允许 fork，可创建独立的远程历史分支。新分支仍是仅历史模式。
7. 点击关闭返回原来的本地交互会话。刷新浏览器时，Blade 使用 URL 中的不透明
   locator 恢复远程历史，而不是使用显示路径。

仅历史模式下，输入框不可用，Files、Terminal、Browser、code review、rewind、
任务派发和 subagent 操作不会启动。若需要继续远程对话，请从拥有该会话的 ACP
客户端打开它。

## 终端 TUI

使用 `/resume` 打开会话选择器。远程条目采用如下形式：

```text
[remote · offline · history] Fix Windows path handling
C:\Repo · 42 messages · 9/2
```

本地条目继续使用原来的恢复流程。选择远程条目后，会打开全屏历史查看器，并把当前
本地交互会话完整保留在后台。`/fork` 也会使用同一选择器，但只列出可 fork 的会话。

历史查看器按键：

| 按键 | 操作 |
| --- | --- |
| `↑` / `k`、`↓` / `j` | 上下移动当前行 |
| `PageUp` / `PageDown` | 按页滚动；到达顶部时按需加载更早历史 |
| `g` / `Home` | 跳到当前已加载内容顶部，并在可用时请求更早一页 |
| `G` / `End` | 跳到当前已加载内容底部 |
| `/` | 编辑搜索词；`Enter` 确认，`Esc` 取消编辑 |
| `n` / `N` | 在当前已加载页面的搜索结果中向前或向后跳转 |
| `y` | 复制当前消息行 |
| `f` | fork 当前会话；结果仍以远程仅历史模式打开 |
| `Esc` / `q` | 关闭查看器并返回未改变的本地会话 |

## 有界读取与隐私

- 默认每页最多 `50` 条可见消息，接口上限为 `100` 条。
- Web 与 TUI 最多保留最近 `500` 条已加载消息，不会一次性载入完整 transcript。
- 单条内容最多 `256 KiB` UTF-8；单页投影后的 JSON 最多 `512 KiB`。被截断的
  内容会显示明确提示。
- 公共消息只包含稳定的不透明 ID、`user`/`assistant` 角色、文本、时间戳和可选
  截断标记。reasoning、tool call/result、附件原始数据和内部 metadata 不会返回。
- URL 只包含 session ID、`workspaceKind=acp-remote` 与不透明 `workspaceRef`；
  不包含远程路径、descriptor 或 Blade 的宿主状态目录。
- cursor 和 workspace reference 都是有界、可重新校验的标识，不是执行授权。

当 cursor 过期或底层 snapshot 改变时，界面会重新打开当前会话以恢复一致视图；
不会把不同快照的页面静默拼接。

## 本版本不支持

`0.10.129` 不支持从 Web/TUI 启动或继续远程 Agent 回合，也不提供远程目录树、
文件预览或编辑、ACP 命令控制台、交互式远程 PTY、远程 Browser 控制或远程 code
review。这些能力不会回退到 Blade 所在主机执行。

本地会话以及没有远程 workspace owner 的 ACP-local 会话继续沿用原有交互、文件、
终端和路由行为。
