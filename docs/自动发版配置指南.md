# 自动发版配置指南

本文档介绍如何配置 Blade Code 的自动发版功能。

## 📋 方案对比

### 方案一：Release Please（推荐）

**优点**：
- ✅ 自动生成 CHANGELOG
- ✅ 自动更新版本号
- ✅ 基于 Conventional Commits
- ✅ 自动创建 PR 和 Release
- ✅ 更智能，更少手动操作

**工作流程**：
1. 推送代码到 main 分支
2. Release Please 分析 commit 消息
3. 自动创建 Release PR
4. 合并 PR 后自动发布到 npm

**文件**：`.github/workflows/release.yml`

### 方案二：Git Tag 触发

**优点**：
- ✅ 简单直接
- ✅ 完全控制发版时机
- ✅ 适合手动发版流程

**工作流程**：
1. 本地更新版本号
2. 创建 git tag: `git tag v0.5.0`
3. 推送 tag: `git push origin v0.5.0`
4. 自动构建并发布到 npm

**文件**：`.github/workflows/publish.yml`

## 🚀 方案一：Release Please 配置（推荐）

### 1. 准备工作

#### 1.1 创建 npm token

```bash
# 登录 npm
npm login

# 创建 automation token
# 访问: https://www.npmjs.com/settings/<your-username>/tokens
# 创建类型: Automation
```

#### 1.2 添加 GitHub Secrets

1. 访问: `https://github.com/<your-username>/blade-code/settings/secrets/actions`
2. 点击 "New repository secret"
3. 添加 secret:
   - Name: `NPM_TOKEN`
   - Value: 你的 npm token

### 2. 配置文件

已创建文件：`.github/workflows/release.yml`

### 3. 使用 Conventional Commits

从现在开始，所有 commit 消息必须遵循规范：

```bash
# 功能
git commit -m "feat: 添加新功能"
git commit -m "feat(cli): 添加 @ 文件引用功能"

# 修复
git commit -m "fix: 修复压缩系统的内存泄漏"
git commit -m "fix(server): 修复 Web 服务器端口占用问题"

# 文档
git commit -m "docs: 更新 README"
git commit -m "docs(api): 添加 API 使用示例"

# 重构
git commit -m "refactor: 重构工具系统"

# 性能
git commit -m "perf: 优化大文件读取性能"

# 测试
git commit -m "test: 添加压缩系统单元测试"

# 构建
git commit -m "build: 升级 TypeScript 到 5.9"

# CI
git commit -m "ci: 添加自动发布工作流"

# 杂项
git commit -m "chore: 更新依赖"
```

**版本规则**：
- `feat:` → Minor 版本 (0.4.0 → 0.5.0)
- `fix:` → Patch 版本 (0.4.0 → 0.4.1)
- `feat!:` 或 `BREAKING CHANGE:` → Major 版本 (0.4.0 → 1.0.0)

### 4. 工作流程

#### 日常开发

```bash
# 1. 开发新功能
git checkout -b feat/new-feature

# 2. 提交时使用规范的 commit 消息
git commit -m "feat: 添加新功能"

# 3. 推送到 GitHub
git push origin feat/new-feature

# 4. 创建 PR 并合并到 main
```

#### 自动发布

```bash
# 1. 合并 PR 到 main 后
# Release Please 会自动创建一个 Release PR

# 2. 查看 Release PR
# - 自动更新 package.json 版本号
# - 自动更新 CHANGELOG.md
# - 包含所有相关的 commits

# 3. 审查并合并 Release PR
# 合并后会自动：
# - 创建 GitHub Release
# - 发布到 npm
```

### 5. 配置 Release Please

创建 `.github/release-please-config.json`：

```json
{
  "packages": {
    "packages/cli": {
      "release-type": "node",
      "package-name": "blade-code",
      "changelog-path": "CHANGELOG.md"
    }
  }
}
```

创建 `.github/.release-please-manifest.json`：

```json
{
  "packages/cli": "0.4.2"
}
```

## 🏷️ 方案二：Git Tag 配置

### 1. 准备工作

同方案一，需要配置 NPM_TOKEN。

### 2. 配置文件

已创建文件：`.github/workflows/publish.yml`

### 3. 工作流程

#### 准备发版

```bash
# 1. 确保所有测试通过
bun run ready

# 2. 更新版本号（三选一）
bun run release:patch  # 0.4.2 → 0.4.3
bun run release:minor  # 0.4.2 → 0.5.0
bun run release:major  # 0.4.2 → 1.0.0

# 3. 手动更新 CHANGELOG.md（如果需要）

# 4. 提交版本更新
git add .
git commit -m "chore: release v0.5.0"

# 5. 创建 tag
git tag v0.5.0

# 6. 推送代码和 tag
git push origin main
git push origin v0.5.0

# 7. GitHub Actions 会自动构建并发布
```

#### 查看发布状态

```bash
# 访问 GitHub Actions 页面
https://github.com/<your-username>/blade-code/actions

# 查看 npm 发布状态
npm info blade-code
```

## 🔧 高级配置

### 添加发布前检查

修改 workflows 文件，在发布前运行完整检查：

```yaml
- name: Run quality checks
  run: bun run ready

- name: Run security audit
  run: bun audit
```

### 多包发布

如果需要同时发布 CLI 和 VSCode 扩展：

```yaml
- name: Publish CLI to npm
  run: |
    cd packages/cli
    npm publish

- name: Publish VSCode extension
  run: |
    cd packages/vscode
    vsce publish
```

### 添加发布通知

在 workflow 中添加通知步骤：

```yaml
- name: Notify on success
  if: success()
  run: |
    curl -X POST ${{ secrets.WEBHOOK_URL }} \
      -H 'Content-Type: application/json' \
      -d '{"text":"✅ blade-code v${{ steps.release.outputs.tag_name }} 已发布"}'
```

## 📝 最佳实践

### 1. Commit 规范

```bash
# ✅ 好的 commit 消息
feat(cli): add @ file reference feature
fix(server): resolve port conflict issue
docs: update installation guide

# ❌ 不好的 commit 消息
update code
fix bug
改进功能
```

### 2. 版本策略

- **Patch (0.0.x)**: 向后兼容的 bug 修复
- **Minor (0.x.0)**: 向后兼容的新功能
- **Major (x.0.0)**: 不向后兼容的重大变更

### 3. CHANGELOG

使用 Release Please 时会自动生成，但也可以手动维护：

```markdown
# Changelog

## [0.5.0] - 2026-07-30

### Added
- @ 文件引用功能
- 智能压缩系统
- ready 命令

### Fixed
- 修复内存泄漏问题

### Changed
- 改进错误提示
```

### 4. 发布检查清单

发布前确认：
- [ ] 所有测试通过 (`bun run test:all`)
- [ ] 代码质量检查通过 (`bun run ready`)
- [ ] 文档已更新
- [ ] CHANGELOG 已更新（如果手动维护）
- [ ] Breaking changes 已在文档中说明

## 🐛 故障排查

### 发布失败

**问题**：GitHub Actions 失败

**解决**：
```bash
# 1. 查看 Actions 日志
# 访问: https://github.com/<your-username>/blade-code/actions

# 2. 常见问题：
# - NPM_TOKEN 未设置或已过期
# - 测试失败
# - 构建失败
# - 版本号冲突
```

**问题**：npm 发布被拒绝

**解决**：
```bash
# 检查是否已登录
npm whoami

# 检查包名是否可用
npm search blade-code

# 检查版本是否已存在
npm view blade-code versions
```

### Release Please 问题

**问题**：没有创建 Release PR

**解决**：
```bash
# 1. 确认 commit 消息符合规范
git log --oneline

# 2. 手动触发 Release Please
# 访问 Actions 页面手动运行 workflow

# 3. 检查配置文件
cat .github/release-please-config.json
```

## 🎯 推荐方案

根据项目情况选择：

### 小型项目或个人项目
→ **方案二（Git Tag）**
- 简单直接
- 完全控制

### 团队项目或开源项目
→ **方案一（Release Please）**
- 自动化程度高
- 规范化 commit
- 自动生成 CHANGELOG

## ⚡ 快速开始

推荐使用方案一（Release Please）：

```bash
# 1. 添加 NPM_TOKEN 到 GitHub Secrets

# 2. 创建配置文件
mkdir -p .github
# 配置文件已在 .github/workflows/release.yml

# 3. 创建 Release Please 配置
cat > .github/release-please-config.json << 'EOF'
{
  "packages": {
    "packages/cli": {
      "release-type": "node",
      "package-name": "blade-code"
    }
  }
}
EOF

# 4. 创建版本清单
echo '{"packages/cli": "0.4.2"}' > .github/.release-please-manifest.json

# 5. 提交配置
git add .github/
git commit -m "ci: setup automated release workflow"
git push origin main

# 6. 开始使用规范的 commit
git commit -m "feat: add new feature"
git push origin main

# 7. 等待 Release Please 创建 PR，审查并合并即可自动发布！
```
