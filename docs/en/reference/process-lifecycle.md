# Child Process Lifecycle

Blade Code treats commands it launches as an owned process tree. On timeout, cancellation, user termination, or application exit, the caller must wait for the entire tree to complete reclamation before reporting completion.

## Termination Protocol

- POSIX: Child processes start in an independent process group; first send `SIGTERM` to the process group, wait 500ms, then use `SIGKILL` to clean up remaining members.
- Windows: First wait for `taskkill /PID <pid> /T`, wait 500ms, then execute `taskkill /PID <pid> /T /F`. If system commands are unavailable, fall back to directly terminating the child.
- Natural exit: The child's `close` or `error` events release ownership; no further signals are sent to the old PID afterward.
- Admission-gated user commands are an exception: after wrapper `close`, the entire POSIX PGID is first probed; ownership is released and the lease deleted only after confirming no other members or completing group finalize.
- Idempotency: Concurrent termination requests for the same process tree share a single Promise and do not repeat the termination sequence.
- Security boundary: PID 0, PID 1, and Blade's own PID are never used as POSIX process group broadcast targets.

The unified termination implementation is in `packages/cli/src/utils/process/OwnedProcessTree.ts`. Session-owned user commands must also use `CommandAdmissionGate` and durable process leases; they cannot rely solely on `spawnOwnedProcess()` in-process handles, nor should they compose `child.kill()` and timers themselves.

## Integrated Entry Points

- Foreground Bash admission, timeout, abort, and hard process crash recovery;
- Background Bash single-task termination and application exit cleanup;
- ACP local terminal fallback admission, timeout, abort, and hard process crash recovery;
- Command hook timeout, abort, and input write failure;
- Post-edit `type-check` automatic verification for trusted+YOLO Sessions;
- Session-private LSP server startup, request, shutdown, crash restart, and dispose.

PTY terminals and internal query tools that only launch a single fixed binary use their own lifecycle protocols and are outside the scope of this ChildProcess wrapper.

## Session Ownership

- The same session in the same project can only be held by one `SessionRuntime` at a time. Runtime uses atomically created session leases to prevent a second CLI, TUI, ACP, or server runtime from concurrently writing to the same JSONL parent chain.
- Session archive acquires leases for the root and all fork/subagent descendants in stable ID order; any owner or queued/running descendant causes the operation to fail with zero writes. After archiving, all Runtime entry points fail closed before recovering resources; see [Durable Session Archive](/en/reference/session-archive.md) for details.
- Creating a runtime when a live owner exists fails closed and returns `BLADE_SESSION_IN_USE`; rejected input is not written to transcripts, nor are model requests initiated.
- When runtime initialization fails or `dispose()` completes, only leases matching the owner token and its own are released. Leases left by abnormal process exit are reclaimed by the next owner after confirming the PID no longer exists.
- Local foreground Bash and ACP local terminal fallback first start a detached gate that does not execute user commands, writes and fsyncs the `.foreground-processes` lease, then releases the command via pipe. On lease or release write failure, it waits for the entire gate tree to reclaim before returning a structured error, with zero user command execution. The gate also listens on the owner pipe; after hard owner exit it actively terminates attached commands, and the next Runtime's identity-checked reaper covers windows where the wrapper exits simultaneously or does not complete cleanup.
- Foreground leases only contain session/process identity, owner/root PID, platform launch identity, and timestamp, using `0600` files, `0700` directories, and atomic write + fsync; they do not contain commands, cwd, env, stdout/stderr, or credentials. Natural exit, spawn error, timeout, and abort all delete the lease.
- After acquiring the Session lease, a new Runtime first reclaims foreground and background orphan processes, then recovers workspace patch transactions, subagents, and other Runtime resources. TERM/KILL are sent only if the owner has exited and the root PID launch identity still matches; PID reuse, corruption, or oversized sidecars all fail closed. Orphan subagent reconciliation executes the same set of reapers after acquiring child Session leases, then repairs child turn/tool receipts. Remote terminals actually created by ACP clients continue to be owned entirely by the client terminal handle; local leases are only used for ACP local fallback.
- On Linux/macOS, root PID exit cannot be equated with process group exit. The reaper independently probes `kill(-pgid, 0)`: stale leases are cleared only when the PGID no longer exists; when members remain, TERM is sent only to the negative PGID, and after grace KILL is sent only after confirming the root PID has not been reused. If the root PID reappears at any time, the lease is retained and marked protected, with no fallback to that positive PID. Windows does not use this POSIX branch; live-root trees are still managed by `taskkill /PID <pid> /T`.
- The normal close/error paths for foreground, background, and ACP local fallback also share the process-group finalize barrier. Even if a user command starts descendants with `&` and redirects all stdio, terminal ToolResult/TaskOutput can only be published after descendants are reclaimed; when finalize fails, a structured error is returned and the durable lease is retained.
- Background Bash binds to the current session at startup. `WriteStdin`, `TaskOutput`, `KillShell`, and `/tasks` can only read or operate on that session's shell; IDs for other sessions are treated as non-existent.
- Background Bash stdin is held by runtime. `WriteStdin` waits for write callbacks and handles pipe errors; `close_stdin=true` explicitly sends EOF. It fails closed when the process has already exited, stdin is already closed, or the session is missing.
- Eligible foreground Bash defaults to waiting 15 seconds; if still running and the original timeout is later, the same PID is atomically handed off to the background shell registry rather than restarting the command. First the `.background-shells` lease is committed, then the `.foreground-processes` lease is deleted, and finally `auto_backgrounded=true` and `shell_id` are published. When background lease commit fails, it continues waiting for the original foreground process and never duplicates side effects.
- `bashForegroundHandoffMs` can be configured in `config.json` as `1000-300000` milliseconds; `0` disables it. Explicit `run_in_background=true` still returns immediately. Standalone/leading `sleep`, read-only audit subagents, missing Sessions, and calls where timeout is no later than the handoff budget remain foreground.
- Foreground candidates and handed-off commands share independent background admission: at most 16 process-wide, at most 4 per Session. When explicit background calls lack capacity, a retryable `resource_exhausted/background_shell_busy` is returned before user code starts; when automatic handoff lacks capacity, the original foreground command is executed once without replay.
- Turn abort/timeout before handoff terminates and waits for the process tree; after successful handoff, the turn AbortSignal is released, and the process is managed by `TaskOutput`, `KillShell`, Session dispose, process shutdown, or natural exit. stdout/stderr remain the same bounded byte stream before and after handoff.
- ACP handoff retains the real IDE terminal handle and does not fall back to local spawn. Blade registers a hidden remote candidate in the same background registry, exposing the ID only after the budget is reached; after completion, KillShell, or Session dispose, it kills (if needed), reads final output, and releases the terminal sequentially. The ACP protocol does not provide stdin writes, so `WriteStdin` after handoff returns an explicit unsupported error.
- Background Bash first starts a detached gate wrapper that does not execute user commands, writes and fsyncs the durable shell lease, then waits for the gate release byte pipe write callback to succeed before returning the tool result and releasing the actual executable; if lease or gate write fails, the user command executes with zero side effects. Leases only contain session/shell identity, owner/root PID, platform launch identity, and timestamp; they do not contain commands, cwd, env, or output. After a new Runtime acquires the Session lease, it first executes the orphan reaper: process groups/trees are terminated only if the owner identity has exited and the root PID launch identity still matches. Ownership is reverified after the TERM grace period and before sending forced signals. Signals are never sent if the PID has been reused or identity cannot be verified; corrupted or oversized leases fail closed and prevent session recovery.
- For each background Bash, stdout and stderr each only retain the most recent 1 MiB of raw bytes since the last `TaskOutput` consumption; continuous output does not cause runtime memory to grow without bound. Earlier discarded output is measured as cumulative stream bytes, and retained content starts from a valid UTF-8 boundary.
- `TaskOutput` additionally limits model and event surface text by command type above the 1 MiB runtime boundary (3,000-20,000 characters, default 15,000), preserving head and tail and returning `output_truncated`, `stdout_omitted_bytes`, `stderr_omitted_bytes`, and `truncation_info`. TUI, headless, Web SSE, and ACP use the same result and display summary.
- Local foreground Bash and `LocalTerminalService` similarly retain the most recent 1 MiB raw bytes each for stdout/stderr. The capture layer records complete cumulative bytes/UTF-16 chars, retained/omitted bytes, and accounting completeness; model projection then enforces independent character/line budgets. timeout, abort, admission, finalization, sandbox runtime failure, and normal exit can only publish safe projections; retained capture or omitted prefixes cannot be written to errors, metadata, progress, or JSONL.
- ACP remote terminals are a protocol boundary: Blade establishes a 1 MiB retained/projection upper bound on received cumulative merged output, and reports facts with `terminal_output_merged=true`, stdout statistics, and zero stderr statistics; host memory before the IDE client returns `currentOutput` is not controlled by Blade. On remote terminal creation or read failure, Bash fails closed and does not fall back to Blade host execution.
- Foreground Bash progress only contains fixed status and integer statistics, and does not forward raw command output. Committed ToolResult is the sole canonical fact; TUI, Headless, Web realtime/replay/fresh load, and ACP live update generate bounded details through the same projector, with truncation notices always retained on the last line.
- `SessionRuntime.dispose()` waits for all background shell process trees in the current session to complete reclamation, without affecting other active sessions.
- Post-edit automatic verification uses Session-private queues and frozen environments. Only local Sessions that have explicitly passed Workspace Trust and are in `yolo` mode can execute project `type-check` scripts; turn abort, timeout, or runtime dispose all terminate and wait for their owned process trees. ACP, untrusted projects, `default`/`autoEdit`, and projects without declared scripts execute zero.
- LSP servers use the same frozen environment and owned process trees. Each Session exclusively owns connections; after `shutdown`/`exit` timeout, escalation to process tree termination occurs. Web tasks, TUI, headless, Task/Team children, and abnormal initialization must all wait for their own LSP PID reclamation.
- Both foreground and background agents write durable sidecars. Sidecars are committed via atomic rename, `fsync`, and `0600` file permissions, with storage directories using `0700`; public APIs do not return prompts, messages, configuration snapshots, workspaces, or owner PIDs.
- Agent enumeration, output, recovery, and cleanup are isolated by the compound identity of `parent sessionId + canonical projectPath`. The same parent ID in different workspaces cannot read or recover each other's agents.
- Running sidecars record owner PID and platform process launch identity; Session leases use the same identity verification. A new Blade process recovers orphans only after the owner has exited or PID identity changes, and successfully acquires the child lease; legacy records without identity continue conservative PID-based judgment, and recent sidecars without PIDs retain a 30-minute compatibility window.
- Orphan child recovery first executes durable turn/tool crash receipt, then rebuilds the current run's model context from child JSONL, and performs suffix/prefix merging with source history already inherited by the sidecar. It only recovers as completed if there is `turn_completed` and the current run has final assistant text; the rest are recorded as interrupted failed and can be resumed with a new immutable child ID. Corrupted JSONL writes a recovery-failed receipt and prohibits resume, but does not block the parent Session.
- When a child sidecar is already `completed`/`failed` but the parent `Task` has not yet submitted `tool_result`, the parent Runtime adopts the result only after compound owner, child ID, description, explicit type, resume lineage, and bounded terminal result all match. Adoption batches are atomically written to canonical `tool_result`, terminal `subtask_ref`, and parent `turn_aborted(process_restart)` by original tool-call/message identity; normal completion and recovery share the same Task result constructor. When any verification fails, the child is still running/cancelled, or the result is corrupted, it continues writing a generic process restart receipt with `sideEffectsUncertain=true` and does not guess child results.
- Task results adopted at startup are projected only once through standard `tool_result` and `subagent_completed` events, and enter canonical JSONL context before the next Provider request. TUI, Web, Headless, and ACP do not assemble results separately from sidecars; Web live cards and fresh loads both use durable child Session identity, terminal status, and bounded summary.
- `Task(run_in_background=true)` uses an independent completion push protocol. The child terminal sidecar fsyncs first; the Runtime accepts only exact parent Session + canonical workspace, `background=true`, committed Task child ID, type/description/resume lineage, and structurally valid bounded terminal state. Then parent JSONL atomically commits the client-hidden user receipt, 32,000-character result/8,000-character error, and terminal `subtask_ref`, then writes a deterministic `background-subagent-completion:<child-id>` inbox item. Parent ACK is exactly-once authoritative; crashes can recover from receipt or inbox boundaries respectively.
- When an active parent still has background Tasks after Provider end-turn, it waits for completion signals rather than polling; user steering takes priority and can directly start the next pending turn. Idle TUI, Web, and ACP recover the same parent after completion fsync; Headless remains in the shared Agent stream. `TaskOutput` is only retained for explicit status checks, active blocking waits, and truncated full result reading.
- Completions queue at most 100 entries and do not consume the 20-entry count/content budget for user steering; the entire inbox is still constrained by an 8 MiB hard upper bound. Streaming Tasks generate canonical child IDs before tool-use persistence; when a child completes earlier than the running result, late results must not overwrite terminal metadata/ref; Web live early events and fresh reload both use terminal ref as final authority.
- Crash reconciliation reuses normal worktree finalize: interrupted or worktrees containing changes are retained, completed clean worktrees are deleted; worktree leases deleted by old processes are cleared from sidecars.
- Each resume creates a new immutable child ID and records `rootAgentId`, `resumedFrom`, and `resumeDepth`. Children inherit the source transcript and frozen model, permission, tool, system prompt, and isolation configuration; worktree leases continue to be managed by the original owner ID and are not incorrectly taken over by child IDs.
- Resuming subagents directly from TUI, Web, or ACP is only permitted when the parent turn is idle and the durable input queue is empty; the model calling Task `resume_from` during its own active turn still goes through the same persistence and owner verification.
- When session context is missing, background Bash and background agent startup fail closed and do not degrade to globally visible tasks.

## Transcript Commit and Recovery

- Session transcripts use line-by-line JSONL, with newlines as commit boundaries for individual events. When loading, only the final unwrapped and unparseable tail fragment may be ignored, which represents the process exiting mid-append; any wrapped bad record or intermediate corruption fails closed.
- Transcript appends within the same process are serialized per file. Before the first recovery write, the file tail is checked: complete JSON records missing only a newline have the newline added; unparseable crash tails are truncated back to the last committed boundary before appending new events.
- `SessionService`, `PersistentStore`, and runtime resume use the same parsing semantics, avoiding sessions being visible in lists but unrecoverable by CLI, or reading skipping bad lines and subsequent writes continuing to pollute history.
- Each Session turn commits `turn_started` before model execution; normal completion commits `turn_completed`, while failure, cancellation, premature stream closure, or process recovery commit `turn_aborted`. Terminal records include turn ID, cause, and turns/tool-calls/duration metrics, and do not contain user prompts or Provider error body text.
- Turn start and terminal append are verified within the transcript file lock: the same event can be idempotently retried, and a second active turn with a different ID fails closed. A new Runtime only marks an unclosed turn as `process_restart` after acquiring `SessionLease` and confirming the old owner has released.
- Tool execution must first commit durable `tool_call`; CLI/TUI, Web, ACP, Headless, and streaming prelaunch/queued paths uniformly prevent tool startup when this commit fails, and do not allow files, shells, or external side effects without journaling to continue executing. Execution throws, cancellation, and epoch discard always retain the original durable tool-call ID, causing failure results to precisely close corresponding calls.
- After tool execution completes, the corresponding `tool_result` must be durably committed before the result can be published to CLI/TUI, Web, ACP, Headless, written to the next Provider context, or applied in domain projections. Result commit failure uniformly returns `tool_persistence_failed` and stops the current run; no next Provider request is initiated, nor is work driven by that result continued. Side effects may have already occurred at this point, and the durable call remains orphan, to be repaired by the next Runtime's `sideEffectsUncertain` receipt.
- Each model-visible user/control input must be durably committed before the Provider request; each non-empty assistant step must be durably committed before the next Provider request, `structured_output` publication, Goal finalize, or successful terminal. On failure, canonical `message_persistence_failed` is returned, current Runtime memory is rebuilt from JSONL model-context projection, and uncommitted messages are cleared. Streaming deltas may first be displayed as temporary progress but do not constitute success or recovery evidence; failed turns do not acknowledge inbox, and cold start prioritizes re-executing that durable input.
- Terminal Provider `queue_full` is a deterministic exception to the above replay rules: Runtime still commits `turn_aborted(cause=failed)`, but simultaneously acknowledges inbox IDs already claimed by that turn, preventing Web reload, SSE reconnect, or ACP load from automatically replaying by bypassing resource boundaries. Provider outage, `wait_timeout`, cancel, and process crash do not use this exception.
- The final assistant message carries bounded `turnFinalization` receipt in the same batch, recording only turn ID, inbox IDs claimed by that turn, and turns/tool-calls/duration metrics. The normal success path fsyncs `inbox_acknowledged` and `turn_completed` for these inbox IDs as one validated batch, updating the mailbox sidecar only after success. If the process exits after the receipt but before the terminal batch, the new Runtime commits the same completion batch and reloads the sidecar after confirming no orphan tool calls; completed inputs are not replayed, and late follow-ups not listed in the receipt are not accidentally acknowledged.
- Goal completion candidate receipts can additionally embed goal ID, verification attempt, verifier Session, evidence digest, and Goal revision. Goal sidecar finalize is permitted only after final assistant commit; the new Runtime idempotently writes `complete` for exact `verifying/pass` receipts. Cross-file write failure prevents Runtime readiness and retries from JSONL receipts on next startup; stale/mismatched receipts continue to require a fresh verifier.
- After acquiring the Session lease, the new Runtime repairs orphan tool calls in the materialized transcript within the same validated batch. Each orphan first receives a synthetic error `tool_result` explicitly marked with `processRestartRecovery` and `sideEffectsUncertain`, before the active turn commits `turn_aborted(process_restart)`; orphans left by terminated turns are similarly repaired. Repeated recovery does not write duplicate receipts. Calls with pending durable interactions are taken over by dedicated Q&A/permission recovery and are not prematurely closed by generic crash receipts.
- `SessionEventLog` publishes durable turn events by seq as `committed.turn_*`. Web SSE resumption can restore running/idle state based on this; CLI/TUI, Web, ACP, and Headless share the same JSONL lifecycle and do not maintain independent terminal states.
- Web Session SSE is held by the Zustand Session Store's navigation transaction, not by `ChatView` components. `selectSession` first waits for history and new subscriptions to be simultaneously ready, then atomically commits Session state and replaces old connections; active subscriptions are closed only when switching to a temporary session, deleting/archiving the current Session, cancellation, or explicit termination. React StrictMode effect replay, Suspense, or view remount must not close Store-committed connections.
- Provider request retries are only permitted before the first real stream chunk enters the Agent loop. Once content, thinking, usage, or complete tool calls are published upstream, subsequent transport/stream failures must fail closed and cannot replay requests or duplicate tool side effects. Stream idle watchdog timeouts similarly do not automatically retry, avoiding overlapping requests or retry storms after long periods of silence.
- Blade disables internal automatic retries in pi-ai/Provider SDK, handling `408`, `409`, `429`, `5xx`, network failures, and stream closes before the first chunk through a single runtime policy. The policy prioritizes respecting `retry-after-ms` / `Retry-After`, otherwise uses exponential backoff with jitter; single waits are capped at 60 seconds, and all sleeps respond to the turn `AbortSignal`. quota/billing, context overflow, caller abort, and explicit `x-should-retry: false` fail immediately.
- Retry lifecycle projects `scheduled → waiting* → attempt → recovered|exhausted` through unified `provider_retry` LoopEvents. Root foreground turns allow at most 12 additional attempts when model retry count is not explicitly overridden, and backoff and in-flight streams are simultaneously constrained by a default 10-minute hard budget after the first transient error; background/internal sampling maintains original short retries. Events only contain attempt, max retries, mode, bounded delay, recovery budget/remaining time, classified reason, and optional HTTP status; they do not contain Provider response bodies, raw headers, URLs, or credentials. TUI loading, Web StatusBar, ACP `session_info_update._meta["blade/providerRetry"]`, Headless JSONL, and subagent SSE consume the same protocol; meta-events do not count as content chunks and do not trigger stream commit or tool execution.
- Provider physical streams bypass in-process admission by default and rely on real `429`, `retry-after`, and shared circuit-breaker backpressure. Blade creates the process-wide bounded fair scheduler only when `providerRequestConcurrency`, `providerGlobalConcurrency`, or `providerOwnerConcurrency` is explicitly configured; unset layers and foreground/background/internal classes impose no hidden active limit. Once enabled, pending count and retained-footprint bytes remain bounded, queued tickets heartbeat every 15 seconds, and all waits respond to the unified AbortSignal. Permits cover only one real iterator; after error/EOF/consumer return they are released before retry, circuit wait, or fallback. `provider_admission` exposes only sanitized resource kinds and does not persist request bytes, domain/owner/Session identity.
- Sessions within the same process share the Provider circuit through a 128-entry bounded failure-domain registry. Each domain uses a 60-second window with at most 256 samples; after Open expiry only one generation/lease token can own the HalfOpen probe, abort/timeout explicitly abandon, and stale results after lease takeover are ignored. Root foreground final candidates wait within the original recovery deadline, while background/internal and non-final fallback candidates fail-fast. `provider_circuit` only projects sanitized lifecycle and does not persist endpoints, credentials/HMAC, response bodies, or circuit state.
- Each Provider physical attempt is simultaneously constrained by hard total deadline, stall warning, and hard idle timeout. The total deadline starts after admission and is not refreshed by semantic events; warning defaults to 30 seconds and narrows to half under shorter idle timeouts; runtime always retains the same pending `iterator.next()` and cannot start overlapping reads or second requests due to warnings. Exceeding the warning produces `provider_stall: detected`; the next Provider event arrival produces `recovered`; events include bounded duration, warning/hard deadline, stall count, and `outputStarted`, and do not contain Provider payload. Stall meta-events, like retry meta-events, do not count toward replay boundaries, content chunks, stream commits, or tool execution, and are uniformly projected to TUI, Web, ACP, Headless, and subagent SSE. total/idle timeout, caller abort, and failures after partial output still fail closed.
- Automatic compaction is divided into predictive threshold compaction and reactive context-limit recovery. When the Provider returns context errors such as `413`, `context_length_exceeded`, `prompt_too_long`, runtime allows only one reactive compaction execution within the zero-real-output boundary; replay is rejected when any content, thinking, usage, or tool call has appeared, and a second over-limit also fails directly, preventing infinite compaction loops.
- Compaction summaries use one independent three-attempt sampling budget. The internal ChatService disables automatic retries and CompactionService owns classification: `408/409/429`, `5xx`, network, timeout, stream-close, and empty-summary failures may retry with exponential backoff; authentication, permission, invalid-request, and caller-abort failures stop immediately. Context overflow never replays the same payload: within the same total budget the host produces a strictly smaller input by removing re-readable files, dropping the oldest complete tool-call units, then lowering the per-message character cap; inability to shrink further falls back immediately. This prevents Provider and compaction retries from multiplying while safely allowing summary replay because sampling has no tool side effects. Usage and cost from successful empty attempts are accumulated.
- Before retrying the Provider, compaction must first atomically commit the exact replacement context. The JSONL summary part stores bounded `replacementMessages` checkpoint, reason, strategy, pre/post tokens, `sampleAttempts`, `inputReductions`, `messagesOmitted`, `filesOmitted`, and stable `failureReason`; commit failure does not apply in-memory replacement nor retry the Provider. The complete visible transcript remains available for UI, export, and auditing, while the host restores exact continuation records verbatim from the full original transcript. `SessionService.loadSessionModelContext()` loads replacement context and subsequent events only from the latest checkpoint; legacy metadata safely degrades.
- `compaction` LoopEvents uniformly carry `threshold|context_limit|turn_limit` reason, `llm|fallback|snip` strategy, `completed|fallback|failed` outcome, sample/reduction/omission counts, and bounded failure classification. Web displays independent context-limit status during reactive recovery; TUI, Headless JSONL, Server SSE, and ACP `session_info_update._meta["blade/compaction"]` use the same lifecycle and do not write internal summaries or Provider error text into assistant content.
- User-turn rewind does not truncate transcripts but instead appends a `session_rewound` marker. resume, catalog, fork, search, and ContextManager cumulatively calculate valid history through the same projector, and rewound original events are retained for auditing but do not re-enter the model or UI.
- Conversation rewind uses user-authored durable message ID as boundary, removing message/tool/compaction events and corresponding turn lifecycles from that turn onward; session metadata and lineage are unaffected.
- Code rewind accepts only consecutive snapshot suffixes per file. Before execution, post-write hashes and backup integrity for all files are checked; when any file is externally modified, the entire group is rejected and no rewind marker is produced.
- Snapshot manifests are partitioned jointly by canonical workspace hash and session ID. Different workspaces with the same ID do not share snapshots; legacy unpartitioned manifests atomically migrate only when all files belong to the current workspace; mixed or mismatched manifests remain fail closed.
- Rewind must be executed by a session-owned Runtime. Active turns, durable pending input, running background shells, or background agents all block rewind, avoiding races between the recovery process and writes.

## Verification

`packages/cli/tests/integration/process-tree-lifecycle.test.ts` starts a parent process and a descendant that ignores `SIGTERM`, verifying that the parent gets a graceful cleanup opportunity, descendants are ultimately force-reclaimed, and the API returns only after reclamation completes.

Production qualification gates also require `deepseek-v4-flash` and `deepseek-v4-pro` to pass the following real CLI process trajectories:

- The model triggers a Bash process tree that inevitably times out, continues completing recovery tasks using the Write tool after receiving structured `timeout_error`, while verifying no descendant processes remain;
- Parent and subagent respectively start foreground Bash with delayed side effects, and the host hard-kills the Blade owner before tool result; the new Runtime must reclaim identity-matched process trees within respective Session lease critical sections, close orphan tool receipts, and prove the sidecar contains no commands, environment, output, or API keys;
- The shell/gate leader in the parent trajectory must have exited before host `SIGKILL`, while TERM-ignoring delayed descendants still survive in the original PGID; the cold Runtime must not misjudge the lease as stale.
- The model starts background Bash without actively terminating it, ends the headless session normally, then verifies that session dispose has waited for the entire process tree to reclaim.
- The model starts background Bash waiting for input in TUI, Web, and ACP, reads the dynamic `shell_id`, writes and closes stdin via `WriteStdin`, then waits for exit via `TaskOutput`; both Flash and Pro must produce correct host files and all three tool events must be fully visible.
- The model starts background Bash producing over 1 MiB output in TUI, Web, and ACP, then verifies tail markers, structured omitted byte counts, and shared display summary via `TaskOutput`; both Flash and Pro must continue completing host file writes after truncation.
- The model executes foreground Bash once each in production Chromium Web, raw PTY TUI, and real ACP SDK terminal; all six Flash/Pro cells must prove that per-stream or merged retained bytes do not exceed 1 MiB, cumulative bytes are accurate, both tail nonces are visible, both omitted prefix sentinels do not enter the model, DOM, PTY, ACP update, or durable transcript, and process trees, leases, ports, and terminal handles are cleared after completion.
- The first CLI holds the session during tool execution; the second same-session CLI must return a structured occupied error without writing input; after the first CLI exits, the third CLI must recover that session and complete writes and Bash verification.
- An unwrapped truncated JSON record is injected at the end of a complete session; the second CLI must recover original history, complete Write/Bash tasks, and make every line of the final transcript legal JSON again.
